# 学习与复盘总结

## 1. 为什么需要抛弃 RustSBI 的 `console_putchar`？
在原本的实验1中，我们调用了 RustSBI 提供的接口输出字符。这虽然方便，但隐藏了底层硬件的真实面貌。通过自行编写串口驱动，我们了解到了以下关键知识点：
- **MMIO（内存映射I/O）**：设备控制寄存器与普通内存共享同一个地址空间。在 RISC-V 架构下，通过指针解引用即可读写设备状态。
- **轮询（Polling）与中断（Interrupt）**：本实验使用了简单的轮询机制（Spin Loop）等待串口发送完毕（`LSR_TX_IDLE`）。在实际复杂的操作系统中，通常会使用中断来避免 CPU 忙等。

## 2. 踩坑与复盘
- **启动环境调整**：原本的 `tg-rcore-tutorial-ch1` 依赖了内建的 `tg-sbi` 固件（通过 `-bios none` 启动并在 M-mode 下运行）。为了实现纯净的 S-Mode 内核且不引入外部依赖，我们将 `config.toml` 的启动参数改为 `-bios default`，直接利用 QEMU 自带的 OpenSBI。这要求我们将链接脚本的入口地址从 `0x80000000` 修改为 `0x80200000`，彻底分离了固件层和内核层。
- **裸机关机调用**：去除了 `tg-sbi` 后，内核需要自行实现关机逻辑。我们通过内联汇编（`ecall`）重新实现了调用 SBI `SYSTEM_RESET` 扩展的功能，完成了内核生命周期的优雅闭环。
- **Volatile 内存访问**：由于操作的是硬件寄存器，必须使用 `read_volatile` 和 `write_volatile`，否则编译器可能会将这些看似无用的内存读写优化掉，导致驱动失效。

## 3. 金石之声
