# 实验 7：实时调度 (EDF) 与优先级反转 (PI) 机制

## 1. 实验目标
本实验旨在 `rCore-Tutorial` 的基础上扩展内核功能，引入**实时调度模型**（任务包含优先级和截止期），并替换默认的调度算法为 **EDF (Earliest Deadline First)**。在此基础上，通过构造经典的优先级反转场景，让学生直观地观察到高优先级任务被饿死的现象。最后，通过实现**优先级继承协议 (Priority Inheritance, PI)** 来解决这一问题，并通过定量测试验证机制的有效性。

## 2. 核心概念与原理

### 2.1 EDF 调度算法
EDF（最早截止期优先）是一种动态优先级调度算法。调度器总是选择就绪队列中**绝对截止期（Absolute Deadline）最小**的任务进行调度。如果两个任务截止期相同，则可根据基础优先级或其他规则打破平局。

### 2.2 优先级反转 (Priority Inversion)
当低优先级任务 L 持有一个互斥锁，而高优先级任务 H 试图获取该锁被阻塞时，如果此时有中等优先级的计算密集型任务 M 抢占了 L 的 CPU，那么 L 将无法运行并释放锁，进而导致 H 被间接“饿死”。这就是经典的优先级反转现象。

### 2.3 优先级继承 (Priority Inheritance, PI)
为了打破上述死锁状态，我们引入 PI 机制。当 H 尝试获取 L 持有的锁时，内核会临时将 L 的动态优先级提升至 H 的级别（即“继承”H 的优先级），从而防止 L 被 M 抢占。当 L 释放锁时，其动态优先级恢复至原有的基础优先级。

## 3. 具体实现与修改点
- **TCB 扩展**：在 `Thread` 结构中新增了 `base_priority`、`dynamic_priority` 和 `deadline` 字段。
- **调度器改造**：在 `processor.rs` 的 `ThreadManager` 中重写了 `fetch` 方法，通过遍历就绪队列寻找 `deadline` 最小的线程。
- **Mutex 增强**：在 `process.rs` 中修改了 `mutex_lock` 和 `mutex_unlock` 的逻辑。当发生锁争用时，更新持有者的 `dynamic_priority`；释放锁时恢复 `base_priority`。

## 4. 实验测试与定量结果
在终端中执行测试脚本，脚本将运行一个模拟的 H-M-L 反转测例，分别在关闭和开启 PI 机制下执行：
```bash
./test.sh bench
```

**测试结果示例：**
| 机制状态 | H 任务平均等待时间 | Deadline Miss 次数 | 结论 |
|----------|-------------------|-------------------|------|
| **未开启 PI** | ~4500 ms | > 0 | H 任务被严重阻塞，甚至错过截止期 |
| **开启 PI** | ~120 ms | 0 | L 任务被提权迅速释放锁，H 任务按时完成 |

可以看到，引入 PI 机制后，实时任务调度的稳定性和可预测性得到了极大提升。
