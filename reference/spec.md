# 操作系统实验模块标准化生成规范 (Experiment Module Specification)

## 一、 实验目录结构要求
每个实验模块（如 `tg-chX` 或 `tg-rcore-tutorial-ch1-uart` 等）必须包含以下核心文件和目录：

- `src/`：实验代码目录。**要求**：代码必须有合理的中文注释，基于 Rust + RISC-V 64 架构。
- `Cargo.toml`：项目配置文件。**要求**：为满足 GitHub 和 crates.io 的上传要求，必须写好标准的依赖配置。如果需要拉取本地库，必须写明正确的相对路径或通过版本号指定，切忌乱填本地绝对路径（会导致学生 clone 下来后无法在本地运行）。
- `README.md`：标准化且清晰的实验指导文档。**要求**：格式必须严格按照第二部分的规范生成，须使用 Markdown 格式编写，图表应采用纯文本方式绘制（推荐使用 Mermaid 语法）。
- `learn.md`：AI 交互记录与学习建议。**要求**：所有对于学生的建议、解答、AI 对话过程，以及**在编程和调试的过程中遇到的问题、报错与深度复盘（凝练为“金石之声”等高价值内容）**，**绝对不能**放入 `README.md`，必须在文件夹内新生成此文件并存入其中。
- `q&a.md`：AI 需在此文件中撰写并保存对话内容总结摘要，梳理核心问题与解决过程。
- `exercise.md`（可选）：如果是生成需要学生互动的练习任务（而非单纯演示实验），必须包含此文件作为配套的文字类习题及解答的指引（请参考 `tg-ch6/exercise.md`）。
- `test/`（可选）：对应的测试用例或参考答案目录。

## 二、 `README.md` 实验指导书标准模板

生成的 `README.md` 必须严格包含以下结构和对应内容（标题必须原样保留）：

```markdown

[此处填写一句话总结、本章学习目标以及前置知识介绍]

[详细说明本章的练习任务是什么，要求完成哪些核心工作]

## 项目结构
[提供包含中文注释的项目目录树。**注意**：如果是运行后才会生成的文件或目录，必须用中文明确标注“运行后生成”]
例如：
\`\`\`text

├── .cargo/
│   └── config.toml     # Cargo 配置：指定交叉编译目标和 QEMU runner

├── Cargo.toml          # 项目配置与依赖
├── README.md           # 本文档
└── src/
    └── main.rs         # 程序源码：入口、主函数、panic 处理
\`\`\`

## 源码阅读导航索引

## 二、编译与运行
[编译步骤、运行步骤。必须包含预期的输出结果展示，各种表格和输出结果要符合老师的规范，使用适当的中文解释、分割线、指引等]

## 三、操作系统核心概念解释介绍

## 七、思考题
```

## 三、 代码与配置输出规范
1. **中文注释**：`src/` 目录下的所有 Rust 代码必须有合理的中文注释，解释关键逻辑、数据结构和操作系统的原理映射。
2. **输出规范**：所有的终端输出示例、表格展示必须整洁，符合老师的排版要求，带有适当的中文解释说明和分割线（如 `---`）。
3. **Cargo.toml 规范（强制要求）**：
   - 必须将 `repository` 修改为对应的学生仓库子目录链接，例如：`repository = "https://github.com/jerryinsz/ai4ose-lab1-2026s/[当前实验目录名]"`
   - 必须将 `homepage` 修改为学生总仓库链接：`homepage = "https://github.com/jerryinsz/ai4ose-lab1-2026s"`
   - （错误示范：千万不能写成官方仓库地址 `https://github.com/rcore-os/...`）
   - 标签字段必须严格设置为：`keywords = ["ai", "ai4ose", "kernel", "learning", "os"]`
4. **未确定信息（占位符）**：如果在生成过程中有任何不清楚、待确定的信息，请一律使用 `TODO` 填充，并提示用户补充。
